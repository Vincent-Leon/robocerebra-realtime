实时快慢思考基准：第三轮实验结果（2026-10-21）

一、执行器修正（r3）
1. 抽屉内碗的前沿抓取：目标腕部偏航角 ±180° 超出第 7 关节限位，腕部停在约 106°，形成切向夹持，抬升后滑脱。修正为按 180° 对称折叠目标偏航角；抓取后确认双指持握，滑脱时自动重抓一次。
2. 抽象开抽屉时，内容物不随抽屉移动，发生穿插与弹出。r2b 中 Memory_Exploration case6 标准计划的 12/12，是黄油被弹出抽屉后在桌面上完成的，属伪成功。修正为内容物随抽屉平移，位置与人类演示一致。
3. 抽屉内取物改为抽象技能，与抽屉开关、储物盒取放一致。抽屉未开或被上层抽屉阻挡时，仍返回失败。
4. 厨房桌场景（60 个任务中的 5 个）机器人底座高 0.50 m，执行器高度参数改为随底座平移；新增倒伏物体抓取。
结果：12 个试点任务的标准计划从 95/129（73.6%）提升到 116/129（89.9%），无任务退步。

二、计分器 v6 与任务定义问题
问题：官方子目标链要求复现演示的抽屉翻找顺序。智能体采用其他合理顺序时，链在探索步骤处停滞，其后已完成的子目标全部不计。例：Memory_Exploration case8 任务实际已完成，只计 8/15。
修正（R11）：链首连续的开/关步骤不计顺序，各自独立计分（关闭须发生在打开之后）；其余步骤保持有序。
验证：人类演示回放与 v5 完全一致（37/40 任务，400/405 子目标）。
影响：r3 共 110 局，39 局得分变化（case5、case8）；r2b 共 145 局，27 局变化，全部在 case5，r2b 的结论不变。
另一个任务定义问题：60 个任务中有 10 个，评分目标引用了场景定义（BDDL）未声明的站点：7 个是灶台 cook_region，3 个是木托盘 contain_region。这些站点不在提供给模型的区域列表中，各任务都有 1 个子目标对任何规划器不可达，整任务成功的上限为 0。已跑过 LLM 实验的任务中只有 Memory_Exploration case5 受影响。下一轮起区域列表会补上这些站点。

三、Prompt 注入（建议模式）
方法：慢分支关闭思维链，只输出不超过两句的建议，注入快分支（Jev）上下文。注入位置在历史与当前状态之后，不破坏共享前缀。触发条件：开局、技能失败、检测到循环、新消息。
延迟：单次建议延迟中位数 2.0–2.9 s；完整计划在长任务上为 47–98 s。
设置：比较四种方法：仅快·Jev、双分支·完整计划·Jev、双分支·建议注入·Jev、双分支·建议注入·Jev（禁缓存）。共 110 局，每组 5 个种子，全部满足实时性判据，按计分器 v6 计分。
结果：
1. Ideal/case6 E1 与 E3（6 s 窗）：各方法均为 5/5，E3 截止余量 1.7–1.8 s。
2. Memory_Exploration case10、case6：各方法均为 5/5。
3. case8：仅快 5/5，建议注入 5/5（禁缓存 5/5），完整计划 4/5。完整计划平均失败技能 8.0 次，其余方法 1.0–2.0 次。
4. case5（14 个子目标）：各方法整任务成功均为 0/5。子目标完成率 / 用时 / 失败技能数：
   仅快·Jev：0.79 / 183 s / 10.0
   双分支·完整计划·Jev：0.81 / 183 s / 18.2
   双分支·建议注入·Jev：0.87 / 102 s / 2.6
   双分支·建议注入·Jev（禁缓存）：0.73 / 205 s / 15.4
   各方法整任务均为 0/5 的原因：子目标"平底锅放到灶台区域"对所有方法都不可达，因为灶台区域不在提供给模型的区域列表中（见第二部分第 2 条），case5 对 LLM 方法的上限为 13/14。建议注入漏掉的只有平底锅的两个子目标：拿起平底锅、放上灶台。
5. 完整计划在长任务上几乎不被采用：来自慢计划的技能只占 0–5%。
6. 建议采纳率（下一个快分支动作的参数出现在建议中）：技能失败后 21/38，开局 10/30，检测到循环后 2/2，新消息后 1/10。
补测（完成判定前先由慢分支核实，case5，5 局）：子目标完成率 0.79（不核实时为 0.87），无改善。关闭思维链的核实建议 3 次均误判平底锅已在灶上，实际上平底锅在桌上的柜子旁；模型得到的信息中没有灶台的位置，无从核对。

四、KV 缓存（vLLM 0.27.1）
1. 命中粒度 784 token 是 vLLM 为 GDN 混合架构自动设定的注意力块大小：align 模式下，注意力页不得小于单层 GDN 状态页。启动日志可证。命中量为 ⌊共享前缀长度 / 784⌋ × 784。
2. 实测 3,551 token 的提示：未命中 1.61 s，命中 0.26 s。请求级 cache_salt 可使命中归零，且不影响其他请求的缓存。后续禁缓存对照改用该方式（r2、r3 用的是系统提示随机串）。
3. 当前提示布局下，易变内容与注入的建议都位于历史之后，不破坏前缀复用。
4. 共享 KV 的效果：Jev 决策延迟中位数 0.42–0.59 s，禁缓存为 0.74–1.25 s。

五、结论与下一步
1. 执行器修正后，试点任务中除 case5 外，各方法均达上限。需要引入更难的任务（更多 Memory、Mix 类任务，长任务叠加事件）来区分方法。
2. 在唯一能区分方法的 case5 上，建议注入在完成率、用时与失败次数上均优于完整计划和仅快；完整计划在长任务上基本不可用。
3. 补上区域列表后重跑 case5；完成判定需要可靠核实：可在核实步骤开启思考，或在状态描述中加入区域关系。
4. 外部模型（OpenAI API 等）的无缓存基线，待确定模型、密钥与预算。
