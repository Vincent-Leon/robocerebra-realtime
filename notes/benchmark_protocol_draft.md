# 基准协议规范（草案 v0.3，2026-10-17 晚）

> 本文把到目前为止实验中确定的设计决定整理成论文"方法 / 基准"部分可直接引用的规范。凡标注【待定】的条目尚未在实验中验证。对应计划文档：`realtime_robot_reasoning_benchmark_plan-2.md` §4–§8。

## 1. 任务与环境

- **底座**：RoboCerebra（NeurIPS 2025 D&B）数据集 `qiukingballball/RoboCerebraBench`，捆绑 LIBERO（robosuite 1.4.1，MuJoCo 3.1.6），Panda 机械臂，OSC_POSE 控制，20 Hz。
- **pilot 子集**（9 个任务文件）：Ideal/case1、3、5、6、8；Memory_Exploration/case3、5、10；Memory_Execution/case5。选择依据：演示回放在修复版计分下可全部完成（见 `RoboCerebra_oracle回放诊断.md`），覆盖 pick / place / pour / open / close / turnon。
- **初始状态**：官方 `init_files`（与演示第 0 帧完全一致），前 15 步空动作静置（与官方 `num_steps_wait=15` 相同）。
- **场景种子**：LIBERO 建环境时随机采样固定装置（无关节的盒子、柜子等）的位置，初始状态文件恢复不了，实测在实例间相差 1–2 cm。固定 `scene_seed=0`，同一任务每个 episode 的场景几何完全一致，方法之间严格配对。

## 2. 固定底层执行器

- 脚本化技能（`exp/skills.py`），使用特权仿真状态做 OSC 比例控制，确定性、可复现；**底层不替决策层做任何排序或选择**。
- 技能：`pick(object)`、`place(region | container)`、`pour(container)`、`open_drawer(region)`、`close_drawer(region)`、`turnon(fixture)`、`wait(n)`。
- 参数来自人类演示统计（抓取偏移、松手高度、倾倒幅度、把手位置，见 E0.6 / E0.7）。
- **抽象技能**（论文中单列标注；每步照常走物理与计分、可取消）：
  - 抽屉开关：机械臂先真实移动到把手前方，再在 40 步（2 s）内线性推动抽屉关节。物理夹持版本（`open_drawer_physical`）开发中。
  - 白色储物盒（前后开口的方框）放入 / 取出：机械臂竖直夹持真实搬到盒口前 10 cm 并降到底板高度，物体位姿在 30 步内线性滑入盒内（或滑到两指之间再夹持）。原因：盒内宽约 12 cm，张开的手指会碰到侧板；人类演示用接近水平的夹爪送入，脚本化复现不稳定。
- **放置位置**：放入抽屉时沿拉出方向外移 0.4 倍半深（之后才能再取出）；放到桌面区域时选末端附近、到基座 0.30–0.60 m、避开各装置几何外框 8 cm 与其他物体的空位，同时偏向机械臂舒适区。
- **姿态保护**：技能开始时若手中物体低于所在容器口，先抬起并朝基座退出；抓取离基座 > 0.65 m 的物体前先回标准姿态（远端易伸直卡在肘关节限位）。
- **中断语义**：每个控制步检查取消标志；取消后机械臂停在当前位置、夹爪保持当前状态（手中物体不自动放下）；取消在下一控制步（≤ 50 ms）生效。
- **前置条件**（执行器拒绝并返回原因）：抓取时手必须为空；放置时手中必须有物体；目标抽屉必须打开；开关抽屉、拧旋钮时手必须为空。这些规则写在所有方法共享的技能说明里。
- **观测一致性**：技能返回后、结果交给规划器之前，仿真立即发布一帧新快照（否则规划器读到的手中物体是旧值，见实验记录 E4.1）。
- **消融开关**：`track_targets`（搬运中持续重读目标位置的闭环执行器），用于区分控制层恢复与语义决策。

## 3. 决策层接口

- 每轮输入：任务文本 + 通用家务规则 + 结构化可观测状态（物体 id 与位置、固定装置、合法区域 id、抽屉开度、手中物体）+ 用户/环境消息 + 历史（技能调用与结果）+ 可选 agentview 图像。【待定】主赛道（仅图像，不给物体位置）。
- **可见性**：关闭（开度 < 0.3）的抽屉里的物体不列出位置，也不出现在候选动作中；打开后才可见。技能说明中固定写明这一点（对所有方法、所有时刻相同，不泄露何时有物体被隐藏），用于保留原任务的探索与记忆要求。
- **通用家务规则**（所有方法共享，系统提示）：倒完把容器放回桌面；结束时夹爪为空。依据：数据集 41 个倒的步骤中 39 个后紧跟"放回桌面"，15/40 个任务原文未写明。
- 输出：单个 JSON 技能调用，或完成声明。双分支的慢分支输出剩余计划（技能列表）。
- **无效输出**：不合法 JSON、未知 id、把装置当放置目标、对非抽屉区域开关等，返回具体原因与合法 id 提示，计入历史；连续 5 次无效则中止。
- **反馈语义**：技能成功与否只由技能自身的**物理后置条件**决定（放置后物体是否在目标区域/物体上、倒时是否在容器上方倾斜、抽屉开度、旋钮角度），**不使用任务计分器的进度**，避免泄露隐藏完成标签（计划 §5.4）。被取消的技能标注取消来源（快速监控 / 环境事件 / 规划器）。

## 4. 时间协议

- **实时闭环**：仿真在主线程按墙钟推进，每控制步对齐到 t₀ + k·Δt / RTR（RTR = 1）；规划器在独立线程，读取带版本号的观测快照；推理期间世界不暂停，无命令时机器人保持姿态、物理继续。
- **有效性判据**：每 20 步采样的滞后最大值 ≤ 0.25 s 且逐步滞后 p95 ≤ 50 ms，否则该 episode 无效并重跑。全速运行的离线任务不得与实时 episode 并发（实测会造成 0.5–60 s 停顿，平均 RTR 掩盖局部违规）。
- **时间戳**：观测采样、命令提交、技能开始/结束/取消、子目标完成、事件触发/截止、规划器思考开始/结束（按分支）、API 重试。
- **对照协议**：Original（官方每子步固定 150 步时间片，可选 resume）；GT 计划"完成即切换"；诊断 oracle（GT 计划 + 固定决策延迟）。

## 5. 动态事件（`exp/events.py`）

| 类型 | 定义 | 触发 | 计分 | 关键指标 |
|---|---|---|---|---|
| E1 目标更新 | 用户消息改变某物体的目的地 | 时间 / 子目标数 / 某技能开始（可加"手持某物体"条件） | 目标列表保留已完成前缀，替换后续 | 进行中的过时技能被取消还是执行完；事件后新提交的过时动作数；有效响应延迟（消息 → 首个指向新目标的命令） |
| E2 容器移动 | 可见地把容器物体在 1.5 s 内平移（SCRIPTED-KINEMATIC） | 同上 | 不变 | 是否重新下发、是否被控制层吸收 |
| E3 限时关闭 | 警告消息；W 秒后抽屉 1 s 内关闭并锁定 | 子目标数（状态触发） | 不变（锁定后无法完成） | 截止前是否完成、余量 |

- 状态触发与时间触发分别报告（计划 §5.6）。【待定】E4（共享资源重排）、E5（缓冲区）。
- **可行性**：用诊断 oracle 在不同决策延迟下验证（E3：时间窗 W 下可容忍的最大每步决策延迟 ≈ W − 3.8 s，空闲机器上干净重跑，见实验记录 E2.7 与 `figs/E3_oracle_frontier.png`）。

## 6. 计分

- **原始计分**：官方 `_check_success`（顺序、只增不减）。
- **修复版计分 v5**（`exp/scoring.py`），对原 goal.json 谓词的文档化放宽 / 收紧：
  - R1 薄片站点（盒子各侧、顶面）→ 体积判定；v5：白色储物盒的 bottom / left / right 侧要求物体中心低于顶板（放在顶板上不算在盒内）；
  - R2 盒装食品的 `pour X Y` 也接受放入 Y；
  - R3' 拿起：靠近末端且抬升 > 4 cm 或离开受监控区域，连续 ≥ 10 帧；
  - R4 `on`：接触且不低于目标、水平距离在目标半径 + 3 cm 内；
  - R5 `open`：关节行程 ≥ 50%；
  - R6' 桌面区域：高出桌面 ≤ 20 cm、不在手中（双指同时接触才算在手中）、且不在任何其他受监控装置区域内；容积型区域放宽顶部容差；
  - R7 `close`：距关闭位置 ≤ 1.5 cm / 0.1 rad；
  - R8 `pour`：在手中、位于容器上方且在上方期间姿态变化 > 0.2；
  - R9 抽屉区域：同一柜子的抽屉区域在高度上重叠，物体按高度就近归属；
  - R10（v5）：in / on 放置类子目标要求物体已离手（双指未同时接触）并连续保持 5 帧（手持物体经过区域、放置途中被取消不算完成）。
- **验证**：40 个任务的演示回放，原始 6/40、修复版 v4 36/40（子目标 61.7% → 97.8%）、v5 37/40（400/405，固定场景）；每次收紧后演示结果都不退步，同时修掉了搬运晃动算倒、掀起算拿起、盒内算桌面、上层抽屉算中层、盒顶算盒内、手持经过算放入六类误给分。
- **计分与执行解耦**：每个实时 episode 保存逐步仿真状态，`exp/rescore.py` 用任意版本计分器离线重算（与在线计分逐帧一致）。

## 7. 指标

- 整任务成功、子目标完成率（两套计分都报告）；完成时间（含失败 episode，按上限截断）；
- 事件指标（见 §5）；规划调用延迟（p50 / p95 / 最大，含 API 重试等待）；每 episode 调用次数与 token；API 重试次数；
- 每组样本量小时只报告 k/n 与范围；【待定】正式规模的置信区间与配对检验。

## 8. 方法与基线

| 名称 | 说明 |
|---|---|
| 统一运行器 | 第二轮起所有方法都用 `run_dual_shared_episode.py` 与同一提示布局，只在决策机制上不同：`--slow=off --fast=text`（仅快）、`--fast=think`（仅慢）、`--fast=jev`（仅快·Jev），`--monitor=off` 为无事件监控消融，`--slow=on` 为双分支 |
| 仅快 | 同一模型关闭思考，顺序"想 → 做" |
| 仅慢 | 同一模型开启思考，顺序"想 → 做" |
| 快 / 慢 + 事件监控 | 技能执行中有新消息时，用关闭思考的同一模型判断是否取消当前技能 |
| 快慢双分支 | 慢分支生成剩余计划；快分支负责兜底决策、计划过时后的语义检查与执行中监控。第二轮协调器：执行每一步前按当前状态判断（效果已成立则跳过；前置条件不满足则作废计划、由快分支接管并请求重新规划）；计划送达时按动作序列对齐，对不上时由快分支判断从哪一步续接，再从当前状态符号化验证剩余步骤，不可执行则整体拒绝并把原因反馈给慢分支 |
| 诊断 oracle | GT 计划 + 固定决策延迟，不读消息 |
| 共享前缀版双分支 | 所有分支共用系统提示与"静态块→只追加历史→图像→当前状态→模式指令"布局（`run_dual_shared_episode.py`），在 L20 自部署实例上运行；`--cache_bust` 为同内容禁缓存对照 |
| Jev 式快分支 | 程序化列出全部合法调用为字母候选，只生成 1 个 token 读概率（`jev_fast.py`），决策约 0.4 s |
| 【待定】双模型、自适应单分支预算（PACE 式）、规则策略 | 计划 §8.1 |

## 9. 可复现性

- 模型：Qwen3.8-27B（支持图像）。两种服务：实验室网关 `sal-pro`（生产服务，无可控前缀缓存，会限流）；L20 单卡自部署实验实例（vLLM 0.27.1，FP8 在线量化，开启前缀缓存与 cached_tokens 统计；混合架构下缓存块为 784 token，只有整块才能复用）。共享前缀与 Jev 的实验只在后者上做。采样用 Qwen3 官方推荐（思考 T=0.6 / top_p=0.95，非思考 T=0.7 / top_p=0.8），每 episode 固定 seed；思考上限 4096 token。
- 记录模型名、服务地址、并发度、重试规则；每配置 3 个种子（pilot）。
- 环境：macOS 26 / M1 Pro 本机仿真，远程调用 L20 推理服务；部署脚本见 `server/`。
