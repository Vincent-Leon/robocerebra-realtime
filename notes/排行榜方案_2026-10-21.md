# 排行榜（leaderboard）方案（2026-10-21）

师兄要求做一个排行榜，对比不同模式的 reward（得分）和 latency（延迟）；参考 VISTA（https://vista-benchmark.org/ ），任务用 RoboCerebra 全部 60 个。

## 参考：VISTA 的排行榜怎么做

VISTA 评测"根据设计稿生成网页应用"的编码智能体。
- **行**：模型 × 运行框架 × 推理强度。
- **列**：
  - 排名；
  - 综合得分（有多轮重复时给"± 标准差"，失败按 0 分计）；
  - 每任务 token 数（只算未命中缓存的输入加输出，避免缓存重读虚增）；
  - 每任务成本；
  - 每任务用时（中位数，只算智能体运行，不含评测）。
- **得分**：在 10 个应用上取平均；重复 3 批，标准差为各批均值之间的标准差。
- **配图**：token 构成的堆叠条形图（缓存输入 / 非缓存输入 / 输出）、每任务用时柱状图、得分随版本变化的折线图。

## 我们的排行榜

### 行（参赛者）
- 模型 Qwen3.8-27B（L20 单卡 vLLM，FP8，前缀缓存）× 5 种模式：
  1. 仅快·文本：每步输出一个 JSON 动作，关思考；
  2. 仅快·Jev：候选打分，每步只生成 1 个 token；
  3. 仅慢：每步开思考后再输出动作；
  4. 双分支·完整计划·Jev：慢分支开思考输出完整计划；
  5. 双分支·建议注入·Jev：慢分支关思考输出 ≤ 2 句建议。
- 消融（不进主榜，单独报告）：禁缓存版本（请求级 `cache_salt`）。
- 后续可加外部模型（OpenAI API 等），需密钥与预算。

### 任务
RoboCerebra 全部 60 个任务：6 类 × 10 个，实际是 40 个不同任务文件配不同运行条件。各类的动态条件与官方评测一致（`exp/rc_dynamics.py`）：

| 类别 | 动态条件 |
|---|---|
| Ideal、Memory_Execution、Memory_Exploration | 无（难点在任务设计：长程、记忆、翻找） |
| Random_Disturbance | 随机扰动：每个子步开始后 0.5 s，把相关或无关物体沿 y 移动 ±0.15 m |
| Observation_Mismatching | 描述错位：从演示第 2 个子步开始，场景已部分完成，规划器要自己发现 |
| Mix | 两者都有 |

与官方协议的差异：
- 官方按固定 7.5 s 时间片切换子步，并在每段重置到演示状态；我们是实时连续执行、完成即切换。
- 因此扰动改为在"当前子步"变化时触发，位移相对当前位置；不移动手中物体、容器或抽屉里的物体。
- 所有差异写在 `rc_dynamics.py` 文件头。

### 列（指标）

| 列 | 定义 |
|---|---|
| 得分（主排序） | 60 个任务子目标完成率的均值。失败、超时按实际完成计；描述错位任务扣除预先完成的子目标后再计。给"± SD"：3 批（3 个随机种子）各自 60 任务均值之间的标准差 |
| 整任务成功率 | 全部子目标完成的任务比例 |
| 分类别得分 | 6 类各自的均值 |
| 单次决策延迟 | 快分支（或仅慢每步）调用延迟的中位数与 p95；双分支另列慢分支单次延迟 |
| 每任务用时 | episode 时长中位数。episode 在全部完成、模型宣布完成、技能次数用尽（40 次）或 300 s 上限时结束，以最先到者为准。原计划"未完成按上限计"，但 60 个任务中只有 24 个对执行器可整任务完成，按上限计会让各模式的中位数都变成 300 s，故改为按实际时长 |
| 每任务 token | 非缓存输入 + 输出（与 VISTA 相同口径）；另画缓存输入 / 非缓存输入 / 输出的堆叠图，体现共享前缀的作用 |
| 每任务 GPU 时间 | 模型服务端占用时间之和（自部署模型的"成本"） |
| 失败技能数、结束原因 | 辅助列：每局失败技能数的中位数；按全部完成 / 宣布完成 / 连续无效回复 / 技能次数用尽 / 时间上限统计局数 |

### 图
- 主榜表格；
- 得分—单次决策延迟散点图（左上最好，标出帕累托前沿）；
- token 构成堆叠条形图；
- 每任务用时柱状图；
- 分类别得分热力图（模式 × 6 类）。

### 规模与时间
- 主榜：5 模式 × 60 任务 × 3 批 = 900 局。
- 每局上限 300 s、40 次技能；按实测，平均每局约 2–3 分钟（仅慢模式多数跑满 300 s）。本机实时仿真最多 2 局并行，约需 20–25 小时，分 3 个晚上跑。
- 若把仿真放到实验室服务器的 CPU 上并行，可明显缩短。
- 开跑前：
  1. 用标准计划（不用语言模型）筛查 60 个任务，得到每个任务的执行器上限，补齐缺失的技能（如微波炉门）；
  2. 用 1 批小规模试跑校准时间。
