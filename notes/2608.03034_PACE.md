## 一句话总结

PACE 在回合制的 Robotouille 同步子集上，把"下一步的思考"按流水线方式记账到"当前动作的参数化执行时长"里（max(t_think, t_exec)），并用"执行窗口 × 推理速度"动态设定 thinking token 预算（软提示 + 强制截断 `</think>`），使 Qwen3-8B-AWQ 的成功率从 ReAct+Think 的 6% 提到 10–13%，思考时间减少 6.9×；但它的"并行"是时间模型层面的核算，环境在推理期间不演化，也没有计划失效问题。

## 问题设定与动机

**三个瓶颈（p.1）：**
1. 推理模型（o1 / DeepSeek-R1 类）单个规划实例的推理延迟常达数分钟，机器人在此期间空转；
2. 现有范式严格串行：必须完成全部推理才开始执行（ReAct 也是如此），执行时间窗口完全没被利用；
3. 推理预算是静态、全局配置的，不随每步的认知难度与执行窗口长短变化——"简单 pick-and-place 与复杂多步装配拿到一样的推理配额"。

**形式化（Sec. III，p.3）：**
- 串行时间模型（Eq. 1）：`T_serial = Σ_{i=0}^{N} (t_think^(i) + t_exec^(i))`。作者实证：ReAct+Think 配置下推理时间占总时长 90% 以上（Table II 中 1334.55 / 1450.42 ≈ 92%）。
- **TDAEP（Time-Delay-Aware Embodied Planning）问题**与流水线时间模型（Eq. 2）：
  `T_pipe = t_think^(0) + Σ_{i=1}^{N} max(t_think^(i), t_exec^(i-1)) + t_exec^(N)`
  三条性质：(a) `T_pipe ≤ T_serial`；(b) 若对所有 i≥1 都有 `t_think^(i) ≤ t_exec^(i-1)`，推理开销只剩首步思考；(c) 可节省的时间 = `Σ min(t_think^(i), t_exec^(i-1))`，即被"藏进"执行窗口的思考时间。
- 评价目标：成功率 SR(π) 与平均总时间 T(π) 的 Pareto 最优（Sec. III.D，p.3）。

**四项贡献（p.2）：** TDAEP 形式化与流水线时间模型；PACE 框架（ITA + DBA）；软提示 + 硬截断的混合预算控制（无需重训）；SR–时间 Pareto 评估框架。

## 核心设计

### 1. 时间模型：动作耗时如何建模

- **动作耗时是查表常数，不是仿真测得的**（Eq. 3，p.3；Sec. V.A，p.5）：
  - `t_move = 3.0 s`（Move）
  - `t_manip = 4.0 s`（Pick, Place, Stack, Unstack）
  - `t_process = 5.0 s`（Cut, Cook, Fry, Boil）
  - 填充类（filling）动作 6.0 s（仅在 Sec. V.A 提到，Eq. 3 中未列）
  - `t_noop`（Do nothing）：Eq. 3 列出了该项但**未给出数值**。
  - 作者称这些值"based on realistic robotic operation times"（p.3），没有给出来源或标定过程。
- **推理时间如何计入：** `t_think^(i)` 是 LLM 实际生成（含 thinking tokens）的 wall-clock 时间（Algorithm 1 第 7 行 `t_i ← think_time(a_i)`，p.6）。即：思考时间是实测的，执行时间是参数表，两者相加/取 max 得到报告的 pipeline time。
- **"执行窗口"的定义：** 当前动作 a_i 的参数化耗时 `t_exec(a_i)` 减去固定开销 `t_overhead = 0.2 s`，再乘推理速度 v 换算成 token 数（见 DBA 公式）。窗口长度在动作选定的那一刻就已精确已知（同步数据集"action execution times are deterministic and known"，p.5）。
- **Gap（p.4，Sec. IV.E）：** 若 `t_think^(i) > t_exec^(i-1)`，产生 `Δ_i = t_think^(i) − t_exec^(i-1)`，"机器人空闲等待下一个动作"。总时间分解为：首步思考（不可避免）+ Σ 执行时间 + Σ 正 gap。DBA 的目标是最小化第三项。作者报告 66.8% 的思考时间被藏进执行窗口。
- **思考隐藏率（think hiding rate）：** 正文定义为"与执行重叠的思考时间占总思考时间的百分比"（Sec. V.C，p.6）；但 Fig. 1 右上角写的公式是 `(T_serial − T_PACE)/T_serial = 66.8%`（p.5），两者不一致（按 Table II 的 PACE 默认行，`(313.63 − 196.78)/313.63 ≈ 37%`，`116.85/192.74 ≈ 61%`，都不是 66.8%；推测表中为逐 episode 平均）。引用时直接引用论文数字，不要自行复算。

### 2. Interleaved Think-Act（ITA）循环（Sec. IV.B，p.4）

三条原则：(a) **首步快响应**：首步只给极小预算 `b_first`（正文"典型 50–100 tokens"，Table I 取 50）；(b) **窗口内前瞻思考**：当前动作执行时推理下一步；(c) **无缝交接保证**：思考应在窗口内结束，否则 DBA 调整后续预算补偿。

正文示例（p.4）：一个 4.0 s 的操作动作 → 约 540 tokens 预算（`⌊(4.0 − 0.2) × 150⌋ − 30 = 540`，与 Table I 参数一致）。"思考提前结束则等执行完；思考超窗则产生 gap。"

### 3. Dynamic Budget Allocator（DBA）：预算分配算法细节（Sec. IV.C，p.4；Algorithm 1 与 Table I，p.6）

```
b_{i+1} = α(s_i, g) · ( ⌊(t_exec(a_i) − t_overhead) · v⌋ − c_output )        (Eq. 4)
Algorithm 1 第 20 行实现为：b_{i+1} ← max(⌊(e_i − t_overhead)·v⌋ − c_output, b_min) · α
```

| 参数 | 值（Table I，p.6） | 含义 |
| --- | --- | --- |
| v | 150 tokens/s | 推理速度（RTX 3090 上 AWQ 模型实测） |
| b_min | 30 tokens | 每步最小预算 |
| b_first | 50 tokens | 首步预算 |
| t_overhead | 0.2 s | 网络/预处理开销 |
| c_output | 30 tokens | 预留给动作输出的 token |
| α 范围 | [0.5, 2.0] | 难度系数 |
| 失败缩放 | ×1.5 | 动作失败后 α 的乘子 |
| 成功缩放 | ×0.8 | 动作成功后 α 的乘子 |

- **α 更新规则有两种表述：** 正文 Sec. IV.C（p.4）写的是离散规则（成功后简单操作 α=0.5；默认 1.0；上一步失败 1.5；连续失败或"critical decision points" 2.0）；Algorithm 1 第 15–19 行与 Fig. 1 写的是乘法更新（失败 `α ← min(α×1.5, 2.0)`，成功 `α ← max(α×0.8, 0.5)`）。以 Algorithm 1 / Table I 为准。"critical decision points" 如何识别未在论文中说明。
- 按 Table I 参数推算（笔者推算，非论文原文）各动作基础预算：Move 390、操作类 540、加工类 690、填充类 840 tokens；α=2.0 时最高 1680，硬上限再 ×1.2 ≈ 2016 tokens。
- 失败判定 `action_failed(o_{i+1})` 来自环境反馈，具体判据未说明。

### 4. Hybrid Budget Control（Sec. IV.D，p.4）

- **软层：** 把预算指令注入 system prompt。预算 <100 tokens → 提示立即给动作；300–600 → 建议多步规划；更大 → 鼓励带依赖图的全面分析。
- **硬层：** thinking tokens 达到预算时，推理引擎强制插入 end-of-thinking 分隔符（`</think>`），迫使模型输出动作。硬预算 = 软预算 × 1.2。
- 消融（Table V，p.9）：只硬截断 SR 5%、只软提示 SR 9% 但思考 674.56 s、隐藏率 25.4%（"soft guidance is weakly followed"）；混合 SR 10%、196.78 s。

### 5. 与环境的交互协议（Algorithm 1，p.6）

```
1: s0, o0 ← E.reset();  α ← 1.0;  b0 ← b_first
4: while ¬d and i < N_max:
5:   p_i ← BuildPrompt(o_i, b_i)
6:   a_i ← π_θ.gen(p_i)            {预算受限生成}
7:   t_i ← think_time(a_i)
8:   o_{i+1}, r, d ← E.step(a_i)   {环境在生成结束后才推进}
9:   e_i ← t_exec(a_i)             {查表}
10-14: T ← T + t_i + e_i (i=0)  否则  T ← T + max(t_i, e_{i-1})
15-19: α 按成败更新
20:  b_{i+1} ← max(⌊(e_i − t_overhead)·v⌋ − c_output, b_min) · α
23-24: 循环结束后 T ← T + e_i   {最后一步执行}
```

要点：
- 环境是回合制的：`E.step(a_i)` 在动作生成之后同步调用，一步完成，没有仿真时钟在 LLM 生成期间推进。
- **第 i 步思考的输入是 `o_i`，而 `o_i` 是 `E.step(a_{i-1})` 返回的、动作 a_{i-1} 执行完毕后的观测。** 也就是说，被记账为"在 a_{i-1} 执行期间完成"的思考，实际上已经看到了 a_{i-1} 的执行结果。这在确定性同步环境里等价于"下一状态可完美预测"，但在有外生事件或执行失败的动态环境中不成立。
- `N_max` 的取值、温度、随机种子、prompt 模板、观测的文本格式均未在论文中给出。PACE agent"继承自 Robotouille 的 ReActAgent 实现"（p.5）。

### 6. 是否真实时间闭环

**不是。** 依据：(a) 动作耗时为参数表而非仿真/实机测量（p.3、p.5）；(b) 只在同步数据集上评测，作者明确选它是因为"deterministic action timing——essential for validating the correctness of our pipeline time model"（p.10）；(c) Algorithm 1 中 pipeline time 用 `max(t_i, e_{i-1})` 解析计算，不存在真正并发的执行线程；(d) 时间从不导致失败：gap 只增加报告时间，没有截止时限、外生事件或计划过时；(e) 作者在 Limitations 中承认"assumes deterministic action timing and perfect execution"（p.10）。

理论分析（Sec. IV.G，p.5）为非形式化陈述：若思考以概率 p 落入窗口，PACE 期望时间 ≤ ReAct-Reasoning 期望时间减去 p 加权的隐藏思考时间；若 SR(b) 对预算 b 凹，则存在 `b* ≪ b_full` 使 `SR(b*) ≥ (1−ε)·SR(b_full)`。无证明。

## 实验与主要结果

### 环境与任务子集（Sec. V.A，p.5；Sec. VIII，p.10）

- Robotouille（ICLR 2025）：共 20 个任务、同步+异步两种模式、200 个测试实例。PACE **只用同步数据集 100 个实例，覆盖 10 个任务类型**，最优步数 10–63。
- 异步数据集（烹饪/油炸等有时间延迟）**未评测**：预试表明 Qwen3-8B-AWQ 即使不限预算也接近零成功（p.10）。
- 参考点（p.10，引自 Robotouille 原文）：GPT-4o + ReAct 在同步集 47%、异步集 11%。

### 基线（Sec. V.B，p.5–6）

IO、IO+Think、ReAct、ReAct+Think（不限预算）、ReAct+Think(HB512)（固定 512-token 硬预算）。所有方法同模型同推理配置。

### 指标（Sec. V.C，p.6）

主指标：成功率、总完成时间（pipeline time）。次指标：步数、累计思考时间、累计执行时间、gap time、思考隐藏率。统计：Wilson 95% CI；成功率用 McNemar 配对检验；时间用 Wilcoxon 符号秩检验；不做多重比较校正（p.6）。

### 关键结论（作者表述）

1. 执行窗口可以用来藏思考时间；PACE 把推理增强规划从分钟级拉到几十秒级（p.9）。
2. 受限推理优于不受限推理（overthinking）；比例分配优于固定预算；加 α 进一步提升。
3. 成功率绝对值低（6–13%）归因于 Robotouille 难度和 8B 量化模型；作者认为相对收益"model-agnostic and scale-independent"（p.10）——这是推测，论文只测了一个模型。

## 与本项目的关系

### 可借用为"自适应单分支预算"基线（计划 8.1）

- PACE 的 DBA 正是计划表中"同模型自适应单分支预算"的现成定义：**预算 = α × (预计可用窗口 − 开销) × 推理速度 − 输出预留**，再配软提示 + 硬截断。这是检验"双分支是否优于更简单的计算分配"（RQ6 的一部分）最自然的对照。
- 建议在我们的实时闭环里按下面方式复现（与 PACE 的差异用粗体标出）：
  1. 下发技能 a_i 时，用一个**技能时长预测器**（PACE 直接查表）估计 `d̂_i`，令慢分支预算 `b = α·(⌊(d̂_i − t_overhead)·v⌋ − c_output)`，v 在我们的硬件上实测。
  2. 慢分支输入是下发时刻的观测 **v0（执行前）**，而不是 PACE 的执行后观测 `o_i`；返回时按计划 6.3 做前提检查。
  3. 思考超窗时，**仿真继续推进**（PACE 里机器人只是记账上"空闲"），按计划 6.3 第 5 条的统一协议继续当前技能/等待/取消。
  4. 子基线：Fixed-100/300/600、Proportional（无 α）、Adaptive（含 α），对应 Table VI。
- 可以同时报告两种时间：PACE 式"解析流水线时间"（`Σ max(t_think, t_exec)`）与我们实测的 wall-clock pipeline time；两者之差本身就是"时间模型 vs 真实闭环"的证据。

### 他们的时间模型与我们的真实时间物理闭环的区别

| 维度 | PACE | 本项目（计划 5–7 节） |
| --- | --- | --- |
| 环境 | 回合制文本厨房（Robotouille 同步集），动作瞬时生效 | LIBERO + OpenVLA 物理仿真，技能按 wall-clock 执行，仿真/真实时间 1:1 |
| 动作耗时 | 参数表（3/4/5/6 s），下发时精确已知 | 技能实际执行时长，有方差，需预测 |
| 推理期间的世界 | 不变（E.step 在生成之后才调用） | 持续演化，含外生事件 |
| "并行" | 单分支、时间核算层面的重叠；思考输入是执行后观测 | 同模型快/慢两分支真正异步，共享 KV 前缀；慢分支基于旧观测版本 |
| 时间与失败的关系 | 时间只是报告指标，不致失败 | 错过事件窗口、计划过时直接导致失败 |
| 计划有效性检查 | 无（无需） | 核心对象（RQ4） |
| 主动争取时间 | 无 | RQ5 |
| 延迟来源 | 仅 LLM 生成时间 | 编码、排队、推理、解析、执行接口，报告 P50/P95 |
| 评测条件 | 最接近计划 7.1 的"暂停环境参考"+ 解析时间核算 | 暂停参考 / 真实时间闭环 / 延迟干预三轨 |

因此 PACE 的结果不能用来回答 RQ1、RQ4、RQ5；它主要支持两个与我们相关的经验点：(a) 推理模型存在 overthinking，预算约束本身就能提升成功率；(b) 按窗口长度分配预算优于固定预算。这两点在我们的真实闭环下是否仍成立，正是需要重测的。

## 局限与注意点

**作者自述（Sec. VIII，p.10）：** 只用同步集 100 实例 / 10 任务类型；成功率检验统计功效不足（建议 300+ 实例或多温度种子）；单一模型；仿真假设确定性动作时长与完美执行，未考虑实机的驱动延迟、传感噪声、执行失败与安全约束；只看成功率不看方案质量（50 步与最优 10 步同分）；α 规则为启发式。

**笔者补充：**
1. **观测泄漏式的"并行"：** 第 i 步思考使用 a_{i-1} 执行后的观测 `o_i`，却被记账为与 a_{i-1} 的执行重叠。等价于假设下一状态可完美预知。这是 PACE 与任何真实异步系统最本质的差别。
2. **时间不进入成功判定：** 没有时限、事件或计划过时，"gap"只是加时。所以 PACE 无法暴露计划失效问题。
3. **数值自洽性：** (a) 正文与 Table II 的 CI 不一致；(b) Fig. 1 的隐藏率公式与正文定义不一致，且无法由表中聚合列复算；(c) Table VI 中 Fixed-Med 的 gap 仅 2.73 s，但其 pipeline（174.30 s）≈ 思考（171.57 s）远大于执行（106.46 s，取自 Table VII 同配置 300-token 行），与 Sec. IV.E 的分解式不符；(d) α 规则在正文与算法中表述不同；(e) b_first 正文"50–100"、表中 50；(f) 预算扫描"10 档"实列 9 档。引用时只用论文直接给出的数字并注明来源表。
4. **未说明项：** N_max、温度/种子、prompt 模板、观测文本格式、PACE-A/B/C 配置差异、"critical decision points" 判定、`t_noop` 取值、失败判据。
5. **外推性：** 作者称收益"model-agnostic and scale-independent"（p.10），但只有一个 8B 量化模型的证据；更强模型思考更短/更长都会改变窗口匹配度。
6. **动作耗时来源：** "realistic robotic operation times"无出处；3–6 s 的窗口与 150 tok/s 的组合决定了 390–840 tokens 的预算档，换硬件或换模型需重新标定。
7. 理论分析（IV.G）无证明，属于直观陈述。
